# Setting the page before the press

A publication can be edited as data and still be read as pages. This specimen is the first proof of that idea. It is not the finished book, and it does not borrow an identity from the InDesign file that will arrive later. The name on the running head, the paper color in the browser, and the green-black accent are placeholders. They live in CSS tokens so they can be replaced without rewriting a chapter.

The work is split on purpose. Words, dates, tables, and labels live with the content. The way a page looks lives with the components, the layouts, and the style sheets. A timeline is not a run of paragraphs that happens to mention dates. An infographic is not a timeline turned on its side. Each strategy has a boundary, so a later change to the art does not melt the text, and a later change to the text does not require the art to be drawn again.

What you see in the browser is the editing view. The sheet is the trim size — A4 until the tokens say otherwise — and the type is the type the PDF embeds. The browser does not break this essay into folios. Pagination belongs to the rendering engine. That engine is a command, not a component, and it can be replaced without rewriting the manuscript. The engine used here is Vivliostyle CLI. It understands CSS paged media. It is not the place where the book is written.

## A flow is allowed to move

This opening is flow. The paragraphs have no assigned page. A pull quote, a note, and the headings travel with the text, and the style sheet asks the paginator to keep a heading with the line that follows it. Widows and orphans are set so a paragraph does not leave a short remnant at the edge of a page. None of those requests are a promise from the browser. They are instructions to the PDF engine, and they have to be checked on the generated pages.

<PullQuote attribution="House rule, provisional">

Keep the manuscript portable. Let the page be a rendering of the manuscript, not the file the manuscript is trapped in.

</PullQuote>

The same rule is why this project does not treat a design application as the runtime. The InDesign document, when it is available, is a visual reference: trim, margins, type sizes, and the rhythm of a real page. It is not a dependency of the preview, and it is not something the PDF command opens.

<HighlightBox title="Placeholder identity" variant="note">

Specimen is a working title. Colors, margins, and the A4 trim are configurable defaults. Do not treat them as the brand, and do not treat the print layout PDF as a certified press file.

</HighlightBox>

The next pages of this file keep the same separation. One of them is still prose, with a diagram and a table in the stream. One of them is a chronology whose events refuse to be ordinary paragraphs. The last one is a single composed sheet, where the JSON supplies values and the layout decides where those values sit. If a sentence on that last sheet grows, the page does not politely reflow. Someone has to design the change.

## Three compositions

Flow is the strategy for chapters, columns, figures, tables, and captions. The objects may start a new page, but they do not bring their own coordinate system. A figure stays with its caption because the style asks for that, and because the component will not render a picture that has no caption. A table is the same kind of object: a caption, a header, and rows, kept intact when the sample is short.

Structured pages are for sequences that have a shape before anyone draws them. The chronology later in this specimen is a list of events. Each event has a date label, a title, and one or more paragraphs. Some events are a single sentence. One of them is deliberately longer, with two paragraphs of uneven length, so the sample is not a row of identical cards. The layout keeps an event together when the text block can hold it, so a heading is not left at the foot of a page while its paragraph starts the next one. An event taller than the text block is a different problem. The request to keep it together cannot be honored then, and the copy has to be cut or the rule revisited.

Art-directed pages are the exception we allow on purpose. The last sheet is one composition. Its regions are placed by the layout. The data behind it is a kicker, three figures of merit, four steps, and a footnote. Adding a paragraph there is a design decision, because the page is not free to grow the way a chapter is.

## Two files, one manuscript

From this source the project can write two PDFs. The digital file is for reading on a screen: the trim, no bleed, and RGB color as the engine painted it. The print layout file uses the same words and a different page configuration. It reserves a bleed and draws crop marks through the rendering engine. It does not convert color to CMYK. It does not embed an ICC profile. It is not a PDF/X file. Those steps, if a printer requires them, stay outside this repository until they are actually run and checked.

That honesty is part of the specimen. A page can look finished and still be the wrong file for a press. The command that builds a PDF records which profile it used. The profile changes geometry. It does not upgrade the color model by wishing.

When the reference document arrives, the first task is measurement, not decoration. Page size, margins, the type scale, and the real sequence of sections should replace these tokens and this sample copy. Until then, the sheets in this file are enough to prove the pipeline: a flowing opening, a second flow with a figure and a table, a chronology of uneven events, and one art-directed page. The count of pages is a result of pagination. It is not a number typed into the manuscript.
